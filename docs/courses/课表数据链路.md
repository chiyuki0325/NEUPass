# 课表数据链路

## 模型与展示

- `Course`保存一条课程安排，供详情和编辑使用。
- `RenderedCourse`保存某一天的展示信息，供日视图、周视图和日历导出使用，通过`key`关联`Course`。
- `Exam`保存考试安排，`renderExams`在加载时将其转换为`RenderedExam`，日期和起止时间使用解析后的类型，展示字段直接放在模型中。渲染结果只保存在内存中。
- `CoursesViewModel`根据当前时间将`RenderedExam`分为待考和已考，通过`ExamState`提供给页面，同时维护课表日期、学期和详情状态。
- `CourseGenre`表示课程分类，显示名称和Fluent图标直接定义在`models/CourseModels.kt`的枚举中。
- 两校区的节次时间统一由`services/courses/CourseRenderer.kt`提供，渲染和编辑预览共用。

## 导入与编辑

`CourseImportService`通过`JwappRepository`获取数据，交给`CourseImportParser`解析，再调用`CourseRepository.replaceManagedCourses`保存。导入消息通过回调交给ViewModel累积展示。

`CourseRepository`维护导入课程、自定义课程、考试和按日期渲染的数据。重新导入时替换导入课程与考试，保留新版仓库里的自定义课程。新增、修改和删除课程后，仓库使用`renderCourses`重新生成每日数据，删除已失效的日期记录。

编辑页通过仓库读取和保存`Course`，保留课程编号、教学班编号和上课班级。详情使用同一份数据。导入成功回调、编辑页的`SAVED`或`DELETED`结果触发`CoursesViewModel.reloadCourses`，重新加载学期、每日课表和考试；取消和普通返回只切换页面。

## 页面与展示状态

`CoursesScreen`负责概览、导入和编辑之间的导航，动画直接以目标页面为状态。日课表、周课表和考试是概览下的三种视图，选择状态放在页面分支外，进出导入或编辑后保留。

`CoursesViewModel`初始化时加载本地数据，日课表和周课表订阅同一个`coursesByDate`，考试页订阅`exams`。页面不再各自读盘、保存课程副本或监听生命周期刷新数据。编辑导航通过Screen传入的回调完成，ViewModel只维护选中的详情课程。

Screen在前台恢复时以及前台每分钟调用`updateTime`，更新今天日期和待考、已考分类，不重新读盘。跨天时，原本停在今天的日期随之更新；用户主动查看的其他日期保持不变。

## 日历导出

common仓库读取每日渲染结果，由`CourseCalendar.kt`生成ICS，课程时间采用`Asia/Shanghai`。平台接口接收生成后的文本：Android写入临时文件并通过系统交付；Desktop和iOS保留原有空实现。

## 存储边界

全部业务只读写`course_v2_*`存储键。旧数据直接弃用，不做迁移或兼容；原有用户需要重新导入教务课程，自定义课程需要重新录入。

不专门处理旧版磁盘数据。退出登录时，`CourseRepository.clearAllData`只清理新版课程、渲染结果、考试和学期信息。
