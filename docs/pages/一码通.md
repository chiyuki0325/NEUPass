# 一码通页面

## 页面概览

- 页面名称：一码通
- 页面用途：展示可供校园闸机和消费终端扫码的一码通二维码，以及当前用户身份和二维码生成时间。
- 路由：主导航 `ecode` 区域
- 页面入口文件：`shared/src/commonMain/kotlin/ink/chyk/pass/features/ecode/ECodeScreen.kt`
- 文档维护范围：一码通首页的二维码、身份信息、刷新行为、网络状态和平台显示效果。

## 页面布局

1. **全局区域**：页面位于四个主区域之一，由应用根导航保留各区域的返回栈。
2. **页面头部**：居中显示 NEUPass 标志与“一码通”标题；点击标志可进入模拟一码通页面。
3. **主要内容区**：显示二维码、加载指示或断网图标。二维码采用白色背景和绿色码点，中间叠加一码通图标。
4. **身份信息区**：二维码下方显示学号、姓名、单位和生成时间。开启隐私遮掩时，学号与姓名改用固定的脱敏展示内容。
5. **刷新操作**：下拉页面或点击二维码、断网占位均会重新请求二维码。

窄屏和横屏均保持单列居中布局；二维码大小会按可用宽高缩放，并限制在 120–220 dp 之间。

## 用户流程与交互

- 进入页面：获取用户信息和二维码；二维码到期后自动刷新。
- 手动刷新：下拉页面，或点击二维码及断网占位。
- 模拟一码通：点击页面头部标志进入模拟页面。
- 返回或离开：离开组合后停止自动刷新；平台显示效果随页面进入和离开恢复。
- 外部依赖：需要有效的统一认证登录状态、一码通会话和网络连接。

## 页面状态

### 加载中

二维码区域显示进度指示，身份信息位置显示“加载中…”。

### 空状态

服务端响应成功但未返回二维码时，页面说明生成失败；用户可以下拉重试。

### 正常状态

显示二维码、用户身份和生成时间。iOS 使用系统 Core Image 生成与 Android、Desktop 相同用途的逻辑二维码矩阵。

### 校验失败

不适用；本页面没有用户输入字段。

### 权限不足或不可用

二维码生成不申请系统权限。Android 与 iOS 会根据“提高一码通亮度”设置，在 7:00–22:00 进入页面时提高屏幕亮度，并在离开页面后恢复原亮度。

### 加载失败

网络或会话请求失败时显示断网占位和失败说明；点击占位或下拉页面可重试。

### 成功反馈

请求成功后直接替换二维码并更新时间，不额外弹出提示。

## 响应式行为

- 窄屏：单列居中，二维码通常按屏幕宽度的 58% 显示。
- 中等屏幕：二维码继续保持单列，并限制最大尺寸。
- 宽屏：二维码最大为 220 dp，不随窗口无限放大。

## 可访问性

- 页面主标题：“一码通”。
- 键盘操作：Desktop 可聚焦并触发二维码刷新入口；移动端支持点击和下拉刷新。
- 语义与标签：标志和断网占位提供内容说明；二维码刷新区域可点击。
- 动态反馈：加载状态由进度指示呈现，失败状态同时提供图形与文字说明。
- 对比度与状态：二维码使用绿色码点与白色背景；加载和失败状态不只依赖颜色区分。

## 依赖与假设

- 依赖：统一认证、一码通会话、Ktor 网络层、平台二维码矩阵生成能力。
- 假设：后端返回的 `qrCode` 是可直接编码的扫码内容，依据当前 Android/Desktop 实现和接口模型。
- 待确认事项：无。
