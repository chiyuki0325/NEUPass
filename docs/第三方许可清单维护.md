# 第三方许可清单维护

## 数据来源

应用中的“开源软件许可”页面使用仓库内的`open_source_licenses.json`，不在运行时下载许可证。

`updateOpenSourceLicenses`先导出三个模块的依赖元数据和实际运行时产物，再运行`scripts/update_open_source_licenses.py`生成页面资源：

- 以非测试运行时配置及Android核心库脱糖配置的解析结果确定组件，合并同一多平台库的不同平台产物，并在详情中列出坐标。
- 从JAR、AAR及其内嵌JAR提取LICENSE、NOTICE、COPYING、COPYRIGHT和AUTHORS，按正文内容去重，保留实际版权文本。
- 对元数据缺失、标错或只有通用MIT/BSD模板的组件，用补充来源中的真实许可证及版权告知替代。
- 构建用的AboutLibraries插件、Gradle和测试框架不作为应用运行时组件列入页面。

当前Linux环境能够解析Android和当前架构的Desktop运行时。Apple专用Ktor引擎及源码构建的MMKV已显式补充；iOS最终分发包和其他Desktop架构仍需在相应发布环境核对实际产物。

## 原生组件与素材

- Navigation3、Pangu：使用上游源码直接编译，许可与源码链接按上游记录。
- KmmResource：保留KuiklyBase上游完整许可证、IceRock相关告知及维护fork的NOTICE，源码链接指向公开的NEUPass维护仓库。
- mmkv-kotlin：保留携程封装的Apache-2.0许可证，源码构建版本单独列入；MMKV核心另附对应版本的完整许可证及第三方告知。
- ComposeNativeWebview：按对应源码版本的Apache-2.0许可证处理，覆盖POM中的MIT标注，项目链接指向上游。
- WebView原生依赖：使用对应上游提交的Cargo.lock收集跨平台及构建期依赖。优先读取发布crate中的许可证；缺失时按crate记录的源码提交查找工作区根许可证。历史提交没有独立许可文件时补取上游现有文件。此清单是跨平台依赖的并集，不表示每个安装包都包含全部条目。
- Rust包的详情提供该版本源码压缩包链接；手动补充的双许可选择与版权声明记录在`rustOverrides`。
- Skia：版本与Skiko的预编译依赖一致，读取Skia发布包中已有的第三方告知，并补充对应DEPS提交的FreeType、ICU、JPEG、Expat、PIEX、Wuffs和DNG SDK许可。FreeType采用FTL选项。
- Fluent UI System Icons：附Microsoft的MIT许可证。
- Roboto数字子集：按字体内嵌的SIL OFL-1.1处理，附Roboto上游OFL正文。
- Golang图标：与Font Awesome 6.7.2品牌图标的路径命令一致，坐标小数精度调整产生的差异不超过0.05；附Fonticons署名、许可说明和CC BY4.0正文，注明应用内的格式、坐标小数精度及填充色调整。
- 腾讯X5：附Tencent Binary License。它是第三方专有组件，不标注为开源许可证。

许可证页面展示文字不替代其他分发义务。发布时还需保留各发行产物原有的许可文件；Desktop若打包Java运行时，也要保留其`legal`目录。使用MPL等许可证的原生依赖时，须保留对应版本源码的获取途径；如修改了受这些许可证约束的文件，还需提供修改后的对应源码。

## 尚待核实

以下素材没有在当前仓库中找到足以确定授权的来源记录，尚未将其标成某种开源许可证：

- `shared/src/commonMain/resources/MR/fonts/iconfont.ttf`。
- `neko*`、`potato_server`、`no_internet`等插画，以及其他非Fluent的业务图标和标志。

这些素材经多次转载取得，当前保留现有文件，不将其标注为某种已确认的开源许可证。

## 更新流程

1. 更新依赖后运行`./gradlew updateOpenSourceLicenses --no-configuration-cache`。
2. 原生依赖版本改变时，核对对应版本的源码和随包内容，更新`scripts/licenses/sources.json`中的来源与版本约束。
3. 检查生成资源中每个组件均有非空正文，没有以通用版权占位符替代上游声明。
4. 至少编译一个目标平台，确认生成资源进入产物，并检查页面入口、返回及许可证详情。
